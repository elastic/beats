**Auditbeat**

[discrete]
[[breaking-https://github.com/elastic/beats/pull/54651-https://github.com/elastic/beats/pull/54811-https://github.com/elastic/beats/pull/54710-https://github.com/elastic/beats/pull/54711]]
.The file_integrity ebpf backend requires the host PID namespace when run in Docker/K8s. https://github.com/elastic/beats/pull/54651[#54651] https://github.com/elastic/beats/pull/54811[#54811] https://github.com/elastic/beats/pull/54710[#54710] https://github.com/elastic/beats/pull/54711[#54711] https://github.com/elastic/beats/issues/54644[#54644]
[%collapsible]
====
The file_integrity module&#39;s ebpf backend now sources file events through
quark instead of the ebpfevents library, removing the dependency on
elastic/ebpfevents and elastic/ebpf. Configuration is unchanged. Each
operation is still reported as its own event, and `file.mode` now reports
only the permission bits, consistent with the `fsnotify` backend.

quark attributes each event to a process by looking up the process ID the
kernel reports in a table built from `/proc` and kept current from kernel
events. The kernel reports host process IDs. When Auditbeat runs in a Docker
container or K8s pod with its own PID namespace, that table is built from the
container&#39;s process IDs instead.

====

[[upgrades-8.19.26]]
=== Upgrades




**Auditbeat**

* Update go-quark for quark 0.8 since-boot timestamps. https://github.com/elastic/beats/pull/54651[#54651] https://github.com/elastic/beats/pull/54811[#54811] https://github.com/elastic/beats/pull/54710[#54710] https://github.com/elastic/beats/pull/54711[#54711] https://github.com/elastic/beats/issues/54644[#54644]
+
quark 0.8 hands out process timestamps as nanoseconds since boot instead of since the epoch. Auditbeat now converts process.start/process.end to wallclock with quark.TimeToWallclock() and keeps quark&#39;s boottime epoch fresh, so timestamps stay correct even when the system clock is stepped, as when NTP corrects a clock that was wrong at boot. Emitted events are unchanged.

* Update go-quark for quark 0.9 boottime handling. https://github.com/elastic/beats/pull/53284[#53284] 
+
quark 0.9 removed quark.TimeToWallclock() and quark.UpdateBoottime(), the boottime epoch from quark.Boottime() is now self-maintaining and only moves on a system clock step. Auditbeat now converts process.start/process.end to wallclock by fetching the epoch once per batch and adding it to quark&#39;s since-boot timestamps, instead of one cgo call per timestamp. Emitted events are unchanged.
